# M6 evaluation guide

## Model settings

The [README example](../README.md#m6-assistant-prefilling) uses a local Qwen3
completions endpoint. Supply the tokenizer from the served checkpoint;
`--m6-tokenizer-revision` can pin its Hugging Face revision. The renderer uses
`enable_thinking=False`, `continue_final_message=True`, and
`add_generation_prompt=False`, then sends token IDs whose sequence ends at the
open assistant box. The user message contains the task and final-answer request.

Select the answer comparator used by the model's evaluation cohort:

| Model | `--m6-accuracy-policy` | Comparison rule |
| --- | --- | --- |
| Qwen3-4B / Qwen3-32B | `canonical_local` | The cohort's normalized exact-match and MATH fallback rules |
| Qwen3-235B / DeepSeek | `legacy_math_rescore` | The cohort's math-verify scoring path |
| Other evaluations | `evaluator` (default) | The repository's standard comparator |

These options apply only to M6. Use the listed cohort policy when reproducing
paper results; `canonical_local` preserves the original normalization behavior.

For DeepSeek, use a model and chat base URL that support assistant prefix
continuation, with these options:

```text
--api chat --provider-profile deepseek_v4 --m6-prefill deepseek-prefix
```

The request ends with an assistant message containing the fixed prefix and
`prefix: true`, with thinking disabled. M6 requires this continuation capability;
ordinary chat and Responses endpoints, including the GPT and Gemini routes,
are unsupported. For those endpoints, select `--modes 1 2 3 4 5`; the evaluator's
default mode list includes M6.

## Metrics

M6 records retain the raw request, raw response, generated continuation, and
full response reconstructed with the assistant prefix.

Acc. uses the first complete box introduced by that prefix. Later corrections
do not replace this answer. ETR requires a nonempty, parseable first boxed
answer and no remaining readable text; whitespace or a single terminal
`.` / `。` is ignored.

For QRel. and EIR, remove the entire initial answer declaration and treat all
remaining readable output as `T`, including separately returned reasoning
fields. The first box is removed even when it contains an expression or
explanation. An unclosed first box remains in `T` and receives zero Acc./ETR.

Use Qwen3-Embedding-4B for the paper's QRel. and GPT-5.5 for EIR. The evaluator's
MiniLM compatibility scores serve a separate purpose. Export one residual Q/T
corpus for both scorers:

```bash
python -m thinking_inertia.m6_prefill \
  --input data/runs/qwen3_4b_m6_prefill/records.jsonl \
  --output outputs/m6_pairs.jsonl
python -m thinking_inertia.metrics.qrel.score_controlled_qrel \
  --input outputs/m6_pairs.jsonl --output-dir outputs/m6_qrel
python -m thinking_inertia.metrics.eir.judge_pairs \
  --input outputs/m6_pairs.jsonl --m6-residual-rubric \
  --model gpt-5.5 --concurrency 24 --batch-size 16 --max-chars 100000 \
  --output outputs/m6_eir.jsonl --errors outputs/m6_eir_errors.jsonl
```

The EIR command uses `OPENAI_API_KEY` and the selected judge endpoint.
Failed or filtered requests stay in the errors file without a label. Report
EIR over valid labels, alongside the denominator and missing count.

## Run directories and M6ᵘ

Start M6 in a new run directory. Trajectories generated with an answer prefix
in the user message are denoted **M6ᵘ**; keep their labels and summaries separate.
The evaluator checks prefill provenance and settings when resuming M6 runs.
